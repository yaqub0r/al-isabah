# Issue 0026 public-boundary remediation

- **Status:** Forward remediated in the current tree
- **Issue:** [#35](https://github.com/yaqub0r/al-isabah/issues/35)
- **Decision type:** Repository policy boundary, not a legal or copyright conclusion

The current tree removes the internal translation-work packet and its detailed
review artifact. Existing Git history, tags, and releases remain intact by
explicit decision. Evidence is preserved through canonical Git blob identities,
byte counts, cryptographic hashes, and the already reachable history; the
repository does not create another copy of the removed material.

The replacement is a strict `public-proposal.v1` projection containing 1,537
records. Automated tests bind the stable IDs, order, titles, Arabic, English,
and preceding bilingual reader content to the accepted v2 baseline hash. Raw
findings, internal autonomous-stage structures, reconstructive operations,
restricted witness wording, internal or private paths, source coordinates,
non-allowlisted URIs, credentials, and unknown fields are excluded recursively.

The exact release closure binds the public proposal and review hashes, source
authority, source register, rights matrix and exclusions, follow-up review,
policy binding, promotion record, review counts, output inventory, and v2
consumer contract. Build and validation fail closed on any mismatch and emit
only normalized paths, categories, counts, and hashes.

## Field classification

| Classification | Retained public representation | Governing basis |
| --- | --- | --- |
| Public | Stable record IDs and order; bilingual titles; approved Arabic and project-authored English; reader-facing preceding material; printed entry and page metadata; visible machine/human state | Translation contract public-output invariant; public-distribution v2 contract; approved OpenITI source record |
| Derived-public | Proposal, order, reader-facing parity, record, source, policy, review-count, and output hashes; normalized finding category/priority codes; minimal honorific occurrence identity | Exact release closure; repository-local policy binding; rights-matrix attribution and integrity rules |
| Restricted/reference-only | Only normalized rights-matrix source ID, role/classification, status/effect code, and hashes may be retained when needed; witness expression is excluded | Source register classifications; canonical repository responsibilities outside public Git |
| Prohibited from public Git | Blind-translation and independent-critique structures; raw witness queries, passages, locations, or narratives; model identity, reasoning, prompts, or responses; raw findings; reconstructive repair operations; private, absolute, internal, source, storage, API, object, or schema locations; credentials or tokens; unknown fields; non-allowlisted URIs | Translation contract evidence/work-product separation; Al-Isabah profile public/private boundary; issue #35 decision |

Marker scanning is defense in depth. The primary controls are the recursive
field allowlist, typed contract, exact source/rights/policy bindings, and output
inventory hashes.

No release, tag, or historical commit was altered. Before any future history
rewrite could be considered, a repository-reviewed evidence-preservation
mechanism and exact authorized sealed destination would be prerequisites. No
such rewrite is part of this remediation.
